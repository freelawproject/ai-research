Sonnet (1-stage)

Sonnet 4.6, single-stage. One LLM call per opinion does both citation extraction and treatment classification. Tested against the Haiku + Kimi two-stage baseline on the 260410 benchmark; currently the best-quality configuration measured.

Architecture

Single LLM stage

Sonnet 4.6 — extract + classify

  • One prompt receives the full opinion in reading order (lead → concurrence → dissent)
  • Identifies each cited case and assigns its treatment label in the same pass
  • Anchors each treatment to a verbatim supporting quote from the opinion
  • Emit a 1–2 sentence rationale connecting the quote to the assigned treatment
  • Output: per-(citing, cited) record with treatment, quote, and rationale
→
Post-process

Canonicalize + derive severity and direction

  • Canonicalize the free-text treatment against the 43-treatment taxonomy
  • Look up severity and direction from the canonical treatment
  • Per-case rollup: most-negative inbound, most-recent-negative
  • Output: the same downstream shape used by all consumers

Everything the model emits is anchored to source text. Predictions that don’t anchor are discarded — the main guard against hallucinated citations or treatments.

Why this configuration

Phase 3’s 17-model bake-off (see Experiments) made Sonnet 4.6 the standout: the only model that returned every citation in the eval set, with treatment-F1 in the same range as the best classification-specialized model. Single-pass keeps the entire opinion in one attention window — no chunking, no inter-stage handoff, no risk that a wrong section boundary in extraction cascades into a wrong treatment in classification. Crucially, the classifier sees the whole opinion when it labels each cited case — treatments are interpretive judgments that depend on surrounding language, the opinion’s posture (majority vs dissent), and cross-references between cited cases. A two-stage pipeline that classifies from a narrow section context loses exactly that signal.

A targeted Kimi K2.5 re-evaluator pass was also tested on top of this configuration and found to do more harm than good — it routes correct Sonnet predictions to Kimi, which then over-flips them. The re-evaluator is not part of the recommended configuration.

Where it shines

Strengths

  • Direct History. Wins decisively on appellate-disposition treatments (Reversed / Affirmed / Vacated / Remanded). Treatment macro F1 ~0.80 on the DH slice. Holds the case’s posture and the appellate action in one attention window — the natural fit for this slice.
  • Cert. denied recovered to F1 0.62 (precision 0.62, recall 0.62) — well above the Haiku + Kimi baseline.
  • Simplest pipeline. One model, one call per page. No re-eval, no stage handoff, no chunking gymnastics — less moving parts means fewer places to regress.

Where it struggles

Weaknesses

  • Cost. ~1.9× the per-case cost of Haiku + Kimi two-stage. Still ~2.2× cheaper than on-demand Sonnet, but the most expensive of the configurations evaluated. See Production cost outlook for the decomposed model and the opinion-size crossover.
  • Cited by → Affirmed by over-attribution. Sonnet sometimes picks up affirmances that should remain Cited by — worth spot-checking and tightening.
  • Long-tail rare classes. Like every configuration tested, struggles on the rare treatments at the bottom of the distribution. Driven primarily by benchmark scarcity, not model capability.
